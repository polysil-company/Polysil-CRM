# API — Users

> Generated by `scripts/generate_api_docs.py`. **Never hand-edit.**
> Base URL: `/api/v1`. Requests need `Authorization: Bearer <access_token>`
> **except** the four endpoints that cannot carry one - `/auth/login`,
> `/auth/otp/verify`, `/auth/refresh` and `/auth/logout` - and anything under
> `/public`.

Conventions for every endpoint in this file:

- Success: `{ "data": ... }`
- Failure: `{ "error": { "code": "...", "message": "..." } }`. Switch on `code`;
  `message` is for a human and may be reworded without notice
- A `422` is schema validation and uses the same envelope, with a `fields`
  map from field path to reason so a form can mark the offending input
- Money is a **decimal string**, never a number: `"1234.56"`
- Timestamps are ISO-8601 UTC; render in IST
- Every POST/PATCH takes `Idempotency-Key`, and replaying returns the first
  response. **The `/auth` mutations are the exception** and take none: login and
  OTP verify are replay-safe through their own ninety-second windows, and refresh
  is rotation, where a repeat is the case the grace window already handles
- Collections accept `page`, `limit`, `sort`, `q` plus the filters listed
- Rows are already scoped by the caller's permissions. An empty list means
  nothing in scope, **not** an error. A `403` means the action is not permitted at all.

## `POST /api/v1/users`

**Create User**

Create a staff member or a partner user.

A staff member needs an email, a non-portal role, an open office and a
temporary password of at least 12 characters; tell them the password out of
band. They must change it at first sign-in, and until they do every other call
they make answers `403 password_change_required`. A partner user needs an
Indian mobile and an active partner; the role is the partner's type and is
never sent. Send `mobile` in any Indian form.

**`Idempotency-Key` is required.** A retry with the same key and body replays
the stored `201`; the same key with a different body (a different password
counts) is `409`.

## `POST /api/v1/users/{user_id}/handover`

**Handover**

Hand every open lead this person owns to someone else, for the leaver's last
day. Pick the target from `GET /leads/assignees`. One call moves at most 500
leads and answers `remaining`; repeat with a **new** `Idempotency-Key` until it
is 0 (a replay under the same key returns the stored answer and moves nothing).
`deactivate: true` also signs the leaver out and deactivates them, and is
refused while anything remains. Zero leads to move is still a 200.
